# Live standalone WAF load test: 750,000 requests, 2026-10-06

The full Carnical executable processed **750,000 measured requests** against a counted loopback origin, retaining the
previous workload and adding six attack categories. It refused **312,695 of 364,553 labelled attack requests (85.77%)**;
**51,858 reached the origin**. No transport errors or availability failures occurred. The run also refused 11,608 labelled
benign requests (3.01%), so these results expose both admission gaps and false positives.

The [admitted-attack inventory](loadtest-750k-admitted-2026-10-06.md) organizes **all 67 admitted attack templates** by
category, with their wire targets, bodies or relevant headers and admission counts. The
[JSON evidence](loadtest-750k-2026-10-06.json) preserves every case's results, category totals and complete synthetic
request details for admitted attacks. The earlier [500,000-request report](loadtest-2026-10-06.md) remains available.

## Workload and research

The original 468 benign corpus cases, 247 attack corpus cases and 16 bypass/valid regressions are retained. The extended
suite adds **211 attack indicators and 27 benign controls** across LDAP, XPath, NoSQL, server-side includes (SSI), HTTP
parameter pollution (HPP) and prototype pollution. These are **969 distinct templates**, each repeated 773 or 774 times;
750,000 is the request count, not the number of unique attacks. The earlier prototype-key regression remains in the
regression cohort, while the added category exercises more prototype paths and transports.

The payloads vary syntax as well as transport: query, form, JSON and XML for LDAP/XPath/SSI; operator objects, Unicode
escapes and bracket notation for NoSQL; duplicate/aliased fields and split injection fragments for HPP; nested, dotted,
bracketed and escaped prototype paths. The [extended suite source](../tools/loadtest/extended.go) defines every new
template and its label. Uppercase `__PROTO__` keys are labelled benign controls for case-sensitive JavaScript parsing,
rather than counted as successful detections of an actual prototype key.

The category selection and application preconditions were checked against primary OWASP guidance:

- [LDAP injection testing](https://owasp.github.io/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Injection/06-LDAP_Injection)
  describes unsafe construction of directory filters; the suite tests filter-closing and boolean/wildcard syntax.
- [XPath injection](https://community.owasp.org/attacks/XPATH_Injection) describes user input changing an application's
  XPath expression; the suite includes booleans, functions, position tests and unions.
- [NoSQL security guidance](https://cheatsheetseries.owasp.org/cheatsheets/NoSQL_Security_Cheat_Sheet.html) calls for validating
  object shapes and preventing untrusted query operators. These indicators require an application accepting those operators.
- [SSI injection](https://community.owasp.org/attacks/Server-Side_Includes_(SSI)_Injection) requires a server interpreting
  user-controlled SSI content; this origin never interprets the submitted directives.
- [HPP testing](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/07-Injection/04-HTTP_Parameter_Pollution/)
  depends on the middleware and backend's handling of duplicate parameters; duplicates alone do not prove an exploit.
- [Prototype pollution testing](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Injection/22-Prototype_Pollution)
  requires unsafe object merging or path setting and an application behavior affected by the polluted value.

## Configuration and measurement boundaries

Windows, Go 1.26.6, 12 logical CPUs; measured interval 2026-10-05 16:33:37-16:35:49 UTC (2026-10-06 in Sydney). This run used
the **same WAF binary as the 500,000-request run**, SHA-256
`f880ae3b6ff1c223d9f6b04348175fa76f73cbc73c1f42f04fb87e3a82bb82d3`.
It embeds revision `32061afd` with `vcs.modified=true`, as explained in the earlier report. This change adds benchmark
templates and reporting; it does not change or tune the measured WAF pipeline.

CRS 4.30.0 ran at default paranoia level 1 and inbound anomaly threshold 5, with CRS and formats in block mode and response
inspection enabled. API quotas and the WordPress flag were disabled. OpenAPI/API guard and virtual-patch integration APIs
were not installed in this standalone executable. The complete launch arguments and corpus hashes are in the evidence.
The ordered suite has SHA-256 `2efb0722b9c2ac2b170392fa900c2ff5c04a917e41b7a79665116451a2646c66`.

The harness launches the actual executable and reverse proxy, waits for readiness and uses 16 unpaced HTTP/1.1 clients.
Connections go only to the local WAF and its counted origin; corpus Host headers do not change the network destination.
The origin always returns fixed JSON and never executes commands, evaluates XPath, queries a database or fetches supplied
URLs. A 200 plus the independent origin count proves request admission, not exploitation.

The URL/framing fidelity fixes from the earlier run remain active: payload `#` characters cannot become client-side
fragments, wire targets are checked, multipart bodies are reconstructed and malformed headers/framing use raw local
connections. No redirects are followed. Refusal includes HTTP-parser, format and CRS rejection; 5xx responses other than
unsupported-method 501 are availability failures and never credited as detections. This is a short local closed-loop
measurement, not a maximum-capacity, distributed or production-duration benchmark.

## What passed and what needs attention

The six added families contributed 163,313 attack requests, with 25,542 admissions: 18 HPP templates and 15 XPath templates.
All tested LDAP, NoSQL, SSI and prototype-pollution attack templates were refused. This describes the tested indicators,
not complete coverage of those families or proof of a dedicated detector for each one.

For **HPP**, query/form duplicates, percent-decoded aliases, array/scalar mixtures, dotted/space-to-underscore collisions,
duplicate booleans and indexed fields pass. A split `q=UNION&q=SELECT+password+FROM+users` passes in both query and form
transports, making origin value-joining semantics a concrete follow-up. All four duplicate-key JSON variants are refused;
the SQL/XSS variants with directly recognizable fragments and raw-semicolon variants are also refused. The form/query
duplicate rules (5002602/5002802) default to Monitor, even when the overall format mode is block; multivalued benign
parameters need an endpoint contract before a blanket duplicate refusal is appropriate. CRS HPP rule 921180 is at PL3 and
is not active at this run's PL1. The admissions establish a test gap, without establishing unsafe origin handling.

For **XPath**, the `true()`, `count(//user)`, `contains(name(),...)`, union and `not(false())` seeds pass in query, form and
JSON transports. Their XML transports are refused. Protecting real XML-search endpoints needs application parameter
binding or a validated input contract plus endpoint-specific regression tests; generic signature refusal alone does not
validate safe XPath construction. The inventory includes the exact encoded bodies and targets.

The original cohort contributes 26,316 attack admissions across the same 34 templates admitted in the earlier run.
Every one of its 731 templates retains the same admission/refusal outcome and response status set. The original cohort's
attack refusal remains 86.92%, with 2.34% benign refusal; the aggregate changes because the workload mix changes. Its gaps
include command strings, serialized Java prefixes, resource URLs, template syntax, scanner identifiers and application
paths. The inventory lists all of them. No vulnerable backend or application sink was exercised.

The four new refused benign templates are uppercase prototype-like query/form/JSON keys and ordinary JSON text containing
the word `__proto__`. The other 11 are the earlier search/editor/API false positives. These need narrow endpoint tuning
against real traffic; the policy was not weakened to improve the benchmark score.

## Validation and reproduction

A 3,000-request pilot under `go run -race` passed with no harness race reports, transport errors or availability failures.
The race detector instrumented the load generator; its child WAF was built normally. `go vet ./carnical/tools/loadtest`
passes. A separate 731-request live compatibility check without `-extended` retains the original suite and its outcomes,
with no transport or availability errors. The final 750,000-request run was conducted separately from CPU-heavy tests.
Review covered request construction,
case labels, fresh bodies, synchronized aggregation, fixed loopback destinations and the absence of production changes.

Post-run checks reconcile every response and origin count, category totals, all 67 admitted templates and all 15 refused
benign templates; verify the unchanged original cohort; and confirm the executable and corpus hashes match the earlier run.
The WAF child process stopped after completion. The JSON file is an exact copy of the final run's output, SHA-256
`2ad1afd78e6ef074dce6ad6fe7dbe192325df5d4804d8f77fb1e450db2bbefbe`.

From the repository root, supplying the owner's separately maintained corpus directory:

```text
go build -o build/carnical.exe ./carnical/cmd/carnical
go run ./carnical/tools/loadtest -binary D:/Dev/coraza/build/carnical.exe -corpus D:/Dev/5Weeks1k/newsletter/content/waf/corpus -output D:/Dev/coraza/build/loadtest-750k.json -extended -count 750000 -concurrency 16
```

Adjust paths for the host. `-extended` selects this workload; omitting it retains the original workload. A rebuild can have
a different executable hash due to VCS metadata or source changes; each report records its own hash. The suite hash binds
the ordered request templates, labels and descriptions. The harness starts and stops its own local WAF and origin.

Raw WAF logs remain local and uncommitted. The 948,174 parsed log events and per-rule counts are a snapshot, include
readiness traffic and can include several events per request. Observed duplicate-field findings include 5,418 form and
10,836 query events across the workload; aggregate counts do not attribute a rule to an individual admitted template.
A forced child shutdown does not guarantee a final flushed format-statistics summary. These checks do not revalidate
Linux confinement, TLS edge termination or the uninstalled integration APIs.
